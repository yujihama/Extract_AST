# 02. エンドユーザーUX原則

この章は、管理者UIとは別に提供する `/u/{usecase}` の体験設計の指針を整理する。

## 原則

1. **成果物中心**
   - 目的は `out/template_filled.md` を最短で得ること。
   - 実行過程（イベント/内部状態）は原則非表示。

2. **段階的開示**
   - 実行中は「状態」と「必要時の入力（HITL）」だけを見せる。
   - 高度設定は折りたたみ（PDF変換など）。

3. **ユースケースの言葉で導線を作る**
   - `/u/{usecase}` に入口を分け、画面文言もユースケースに合わせる。
   - 内部の`mode/step`などは露出させない。

4. **安全性優先**
   - 削除、内部ファイル閲覧、イベントpayloadの露出は避ける。
   - サーバ側でも `/u` では `out/` 以外にアクセスできないようにする。

5. **短い入力で開始できる**
   - 最小の入力: ドキュメント選択/アップロード + 依頼文。
   - 依頼文はレシピごとのテンプレ例で支援する。

## UIの基本構成（想定）

- `/u/{usecase}`: 概要 + 入力例 + 開始ボタン
- `/u/{usecase}/runs/new`: 入力フォーム（最小）
- `/u/{usecase}/runs/{run_id}`: 状態 + 成果物 + HITL
