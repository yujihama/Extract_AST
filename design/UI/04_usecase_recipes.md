# 04. ユースケースとレシピ

`recipe_id` は **ユースケース別の入口** を表す識別子で、UI文言・入力ガイド・推奨設定を束ねる。
Runの内部実行は共通のパイプラインを使い、**recipe_idだけを保存**して分岐は行わない。

## レシピ一覧（初期）

| recipe_id | タイトル | 想定入力 | 目的 |
|---|---|---|---|
| `compliance` | 準拠評価 | 基準 + 対象（複数可） | 適合/不適合/要改善の評価 |
| `gap` | ギャップ分析 | 要求 + 対象（複数可） | 未対応/不足の抽出 |
| `diff` | 差分・改訂影響 | 旧版 + 新版 | 変更点と影響の整理 |
| `extract` | 抽出・構造化 | 単一〜複数 | 義務/条件/定義等の抽出 |
| `summary` | 要約・ブリーフィング | 単一〜複数 | 目的別の要約作成 |

## レシピの持つ情報（例）

- `request_text_template`: 依頼文の雛形
- `default_params`: 推奨設定（`mode=real` など）
- `allowed_artifact_prefixes`: ユーザーがアクセス可能な成果物範囲
- `visible_artifact_kinds`: UIに表示する主成果物の種類

## 追加方針

- 追加は `document_process_app/web/recipes.py` にレコードを追加するだけで良い。
- パイプライン分岐は行わず、`recipe_id` を Run のメタ情報として保存する。
