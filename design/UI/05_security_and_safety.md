# 05. セキュリティ / 安全設計

## 前提

- `/admin` は運用上非公開（VPN/別ホスト/リバプロ制限など）。
- `/u` はエンドユーザー向け公開。
- 認証は最初は導入しないが、**URL分離＋サーバ側ガード**で安全性を担保する。

## エンドユーザー側の制限

- **削除操作の非表示**（Run/Document削除は `/u` で提供しない）。
- **内部情報の非表示**
  - `run.params` の全文表示をしない
  - イベントpayloadの全文表示をしない
- **成果物のアクセス制限**
  - `/u` では `out/` および `work/template_draft.md` のみアクセス可能
  - `work/log/cache` へのアクセスは禁止（サーバ側で遮断）
- **FSスキャンの無効化**
  - `/u` の成果物一覧は `artifacts` テーブルのみを利用

## 運用ガード

- リバプロで `/admin` `/api` を社内限定にする
- `/u/*` のみ外部公開
