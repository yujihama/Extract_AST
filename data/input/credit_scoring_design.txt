【与信審査システム 基本設計書】ver 1.0（架空）

1. システム構成

1.1 全体アーキテクチャ
- フロントエンド: React.js による SPA
- バックエンド: Python (FastAPI)
- データベース: PostgreSQL
- 機械学習基盤: AWS SageMaker
- 外部連携: REST API（信用情報機関）

1.2 システム間連携
- オンライン申込 → 与信審査システム（API）
- 与信審査システム → 信用情報機関（API）
- 与信審査システム → 基幹システム（バッチ連携）
- 与信審査システム → 通知サービス（メール/SMS）

2. 機能設計

2.1 申込データ取込（REQ-F01対応）
- 申込APIはJSON形式でデータを受信
- バリデーション: 必須項目チェック、桁数・形式チェック
- エラー時は400エラーと詳細メッセージを返却

2.2 外部データ連携（REQ-F02対応）
- 信用情報取得は非同期処理（キュー経由）
- タイムアウト: 30秒
- リトライ間隔: 5秒、10秒、30秒の3回

2.3 スコアリング（REQ-F03対応）
- モデル: LightGBM
- 説明変数: 18項目（別紙「変数一覧」参照）
- スコア計算式: ロジスティック変換後、0-1000にスケーリング

2.4 自動判定（REQ-F04対応）
- 判定ロジックはルールエンジンで管理
- ルール変更は設定ファイルで対応（コード変更不要）

2.5 限度額算出（REQ-F05対応）
- スコア連動係数テーブル:
  - 900点以上: 0.4
  - 800-899点: 0.35
  - 700-799点: 0.3
  - 700点未満: 審査担当者判断

3. データベース設計

3.1 主要テーブル
- applications: 申込情報
- credit_reports: 信用情報
- scoring_results: スコアリング結果
- decisions: 審査判定
- audit_logs: 監査ログ

3.2 個人情報の暗号化
- 氏名、住所、電話番号: AES-256で暗号化
- 暗号鍵: AWS KMSで管理

4. セキュリティ設計（REQ-N03対応）

4.1 認証
- 審査担当者: SAML連携によるSSO + OTP（二要素）
- 申込者: 申込番号 + 生年月日による簡易認証

4.2 認可
- ロールベースアクセス制御（RBAC）
- ロール: 審査担当者、審査マネージャー、システム管理者

4.3 ログ
- 全APIリクエスト/レスポンスを記録
- 個人情報はマスキング（氏名: ○○ ○○、電話: ***-****-XXXX）

5. 公平性設計（REQ-N05対応）

5.1 XAI実装
- SHAP値による判定理由の可視化
- 審査担当者画面に「判定理由TOP5」を表示

5.2 公平性検証
- 定期的にモデルのバイアスを検証
- 性別・年齢層別の承認率を監視
