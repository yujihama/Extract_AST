2. 提案概要

2.1 基本方針
「安全・確実な移行」と「将来の拡張性」を両立させた提案

2.2 クラウド基盤
AWS（Amazon Web Services）を採用
- 国内実績No.1のクラウドサービス
- 東京リージョン（ap-northeast-1）を使用
- マルチAZ構成で高可用性を実現

2.3 移行アプローチ
リフト&シフト方式を採用
- 現行システムの構成を維持しつつクラウドへ移行
- 移行リスクを最小化
- 将来的なモダナイゼーションへの発展も視野

3. システム構成

3.1 インフラ構成
- Webサーバー: EC2 (m6i.xlarge) × 4台（2AZ分散）
- APサーバー: EC2 (m6i.2xlarge) × 4台（2AZ分散）
- DBサーバー: RDS for Oracle (db.r6i.2xlarge) MultiAZ
- ストレージ: S3 + EBS (gp3)
- ロードバランサー: ALB

3.2 ネットワーク構成
- Direct Connect (100Mbps) による専用線接続
- VPC内にプライベートサブネットを構成
- セキュリティグループ、NACLによるアクセス制御

3.3 セキュリティ対策
- 通信暗号化: TLS 1.3
- データ暗号化: AES-256（AWS KMS管理）
- 認証: AWS IAM + SAML連携（既存AD）
- 監査ログ: CloudTrail + CloudWatch Logs（保存期間: 400日）

4. 移行計画

4.1 フェーズ構成
- Phase 1（2ヶ月）: 設計・環境構築
- Phase 2（3ヶ月）: 移行準備・テスト
- Phase 3（2ヶ月）: 移行実施・安定化
- Phase 4（2ヶ月）: 運用移行・最適化

4.2 移行方式
- データ移行: AWS DMS（Database Migration Service）使用
- 事前同期により移行時のダウンタイムを最小化
- 移行リハーサルを2回実施

4.3 ダウンタイム
計画ダウンタイム: 6時間
- DB切替: 4時間
- 接続確認・動作確認: 2時間

5. 運用保守計画

5.1 運用体制
- 監視: 24時間365日（NOC常駐）
- 障害対応: 一次対応30分以内、二次対応2時間以内
- 定期作業: パッチ適用、バックアップ確認、性能監視

5.2 SLA
- 稼働率: 99.95%保証
- 計画停止: 月1回、2時間以内
- 障害復旧: RTO 2時間、RPO 15分

5.3 報告
- 月次運用報告書
- 四半期レビュー会議
